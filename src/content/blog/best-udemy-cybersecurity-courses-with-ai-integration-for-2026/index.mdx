## How we picked these courses

- **AI must be in the syllabus, not the subtitle.** We checked the curriculum and learning outcomes for prompt injection, model risk, guardrails, agent behaviour, LLM pentesting, or AI governance. A course that mentions ChatGPT once does not qualify.
- **Real student data.** Every course here has a published rating and enrolment count from the catalogue. We did not include courses we could not verify.
- **Current content.** The courses cover the 2026 toolchain: MCP, agentic frameworks, Claude Code, OWASP LLM risk classes, and the Microsoft SC-500 cloud-and-AI security track.

## A 90-day plan that actually works

**Weeks 1–2 — vocabulary and a first win.** Take #4 or the beginner foundation course. Set up a lab: a virtual machine, a free LLM API key, and a deliberately vulnerable app. Goal: explain prompt injection, data leakage, and excessive agency in your own words.

**Weeks 3–5 — build something and break it.** Start #1 (guardrails, gateways, observability). Build a small RAG app over public documents, then attack it with the techniques from #2 or #3. Log what you tried and what worked. This is the artefact that gets you hired or funded.

**Weeks 6–8 — specialise.** Offensive track: #3 plus PortSwigger's LLM labs, then #8 for MCP. Defensive track: #2 plus detection engineering, then #7 for application-level controls. Keep a public repo with the labs and a short write-up per vulnerability class.

**Weeks 9–10 — governance.** Take #10 or at minimum read the OWASP LLM guidance, NIST AI RMF, and MITRE ATLAS. Write a one-page AI risk register for the app you built: assets, trust boundaries, threats, controls, residual risk, owner. Most candidates cannot produce this document; it is an immediate differentiator.

**Weeks 11–12 — prove it.** Publish the repo, the write-ups, and the risk register. Add the certificate from your main course. Apply to roles that mention LLM security, AI governance, or secure AI engineering — a category that barely existed two years ago and is now listed by banks, consultancies, and cloud providers.

## What changed in AI security in 2026

- **OWASP's LLM risk list became shared vocabulary.** Prompt injection, sensitive information disclosure, supply chain, poisoning, improper output handling, excessive agency, system prompt leakage, embedding weaknesses, misinformation, and unbounded consumption are now how security teams describe AI bugs. Courses that do not use these categories are behind.
- **Agentic risk is its own discipline.** The failure mode is no longer "the model said something bad" but "the agent did something plausible, unauthorised, and expensive". Goal drift, memory poisoning, and multi-agent collusion are the new threat models, which is why #5 exists.
- **MCP is the new perimeter.** Tool-using agents connect to internal systems through MCP servers, and those servers are frequently built by developers with no security review. SSRF, confused deputy, and command injection in an MCP server are the 2026 equivalent of an unauthenticated admin panel.
- **AI coding agents sit inside security teams.** Subagents, hooks, and skills change how code review and triage work, and they introduce a supply-chain question: who reviewed the agent's actions? #9 is the shortest useful answer.
- **Governance stopped being optional.** The NIST AI Risk Management Framework, ISO/IEC 42001, and the EU AI Act's obligations for high-risk systems all require documented risk assessment and controls. That is the market #10 is aimed at.
- **Certifications followed.** Microsoft's SC-500 Cloud and AI Security Engineer is the clearest signal that cloud security and AI security are merging into one job description.
