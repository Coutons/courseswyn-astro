# AGENTS.md

## Repo at a glance

- Static Astro 7 + React 19 site for CoursesWyn. `src/data/coupons.json` (~1.5k deals) generates ~3k pages; a production build takes about 1 minute.
- No test suite and no runtime backend in production. `dist/` is gitignored and untracked.

## Commands

- Install: `npm ci` (Node 24; `.npmrc` sets `legacy-peer-deps=true`).
- Dev server: `npm run dev` → http://localhost:4321.
- Static build: `npm run mode:prod && npm run build`; preview with `npm run preview`. `npm run build` alone follows whatever mode is currently active.
- Verify changes with a successful `npm run build`; there is no `npm test`.
- `npm run lint` is `astro check`, not ESLint, and is not a clean gate. A clean install lacks `@emnapi/core` (peer deps are skipped), so it prompts instead of running; after `npm i --no-save @emnapi/core @emnapi/runtime` it still reports ~32 pre-existing TypeScript errors. Don't block unrelated work on them.

## Dev/prod mode switch (read before touching admin, API, or config)

- `astro.config.mjs` is generated by `scripts/auto-switch.js`. Edit `astro.config.dev.mjs` or `astro.config.prod.mjs`, never the generated file.
- The tracked/default state is production/static mode: admin routes are tracked as `*.astro.disabled`, and `npm run build` emits static `dist/`.
- For admin/API work: `npm run mode:dev`, then `npm run dev`. Return with `npm run mode:prod` before committing.
- Mode switches rewrite tracked files and rename `src/pages/admin/**/*.astro` ↔ `.disabled`; expect those changes in diffs.
- Add any new server-only route to `SERVER_ROUTES` in `scripts/auto-switch.js`; otherwise `mode:prod` leaves it active and breaks the static build.
- Redirects and the sitemap filter live in `astro.config.prod.mjs`; apply config changes to the source config and re-run the mode switch. The filter drops admin/API, search, and paginated routes — add any new noindex route there too.
- Deployment runs via `.github/workflows/deploy.yml` on push to `main`: Node 24 → `npm ci` → `npm run mode:prod` → build → assert `dist/index.html` and `dist/sitemap-index.xml`. `npm run deploy` (git subtree) does not work in this checkout because `dist/` is gitignored.

## Coupon data and routes

- `src/data/coupons.json` is the catalog. `src/lib/store.ts` reads and validates it at build time; required fields are `slug`, `title`, `price`, `category`, `provider`, `url`. Invalid or duplicate records are skipped with a warning.
- `DEALS_PATH` can point to an alternate JSON file or directory (useful for testing data changes without touching the main catalog).
- A deal's `slug` is its route: `/coupon/<slug>/`. Keep slugs unique. Discounts are generally computed from `price`/`originalPrice` (the admin API strips a submitted `discount`); expiry is controlled by `expiresAt`.
- Everything is built statically: "today", expiry, freshness labels, and counts are frozen at build time. Rebuild to refresh them.
- The AWS/CompTIA/Microsoft exam-voucher pages are driven by `src/lib/vouchers.ts`, not `coupons.json`.
- Category and topic routes are generated from names via `slugifyCategory`/`slugifyTopic`; legacy Spanish slug redirects are hardcoded in `astro.config.prod.mjs`.
- All configs force `TZ=Asia/Jakarta`; use `src/lib/date.ts` helpers for displayed dates. Pages are directory URLs with trailing slashes; `Layout.astro` normalizes canonicals.
- API routes under `src/pages/api/` are prerendered snapshots in production (`dist/api/*`), not live endpoints.

## Blog content

- Posts live at `src/content/blog/<slug>/index.md` or `index.mdx`; the directory name is the URL slug. The collection schema in `src/content.config.ts` requires `title`, `description`, and `pubDate`.
- `draft: true` only hides a post from the homepage; it still appears in `/blog`, RSS, and the sitemap. Remove or unpublish posts another way.
- Blog FAQ structured data is parsed from a `## Frequently Asked Questions` section using `### question` headings; follow that format when adding FAQs.
- Admin saves preserve `.mdx` when the body contains imports/JSX and remove the stale sibling `.md` file; keep blog posts as directories, not standalone files.

## Featured images

- Full workflow: `docs/featured-images.md`. Read it before adding or editing a post.
- Every post uses a generated OG card: `image: /assets/images/<slug>.jpg` (1200×630, q84, ~35–45 KB) plus a `<slug>-600.jpg` card variant that `/blog` uses through `srcset`. Don't hand-upload stock images; regenerate instead.
- New article: add a `POST_SPECS` entry in `scripts/og-specs.mjs`, then `npm run og -- --only <slug>`. Posts without an entry still get an auto-derived card, but that is a safety net, not the intended path.
- Other commands: `npm run og` (everything), `npm run og:blog`, `npm run og:pages`, `npm run og:dry` (text-fit report, writes nothing), `npm run og:check` (every expected file exists at 1200×630). The footer date comes from the post's `updatedAt`, so regenerate after changing it.
- Design config lives in `scripts/og-specs.mjs`: one `POST_SPECS` entry per post (`keyword`, `lines`, `category`, `kicker`) and one `PAGE_SPECS` entry per static page (`og-home`, `og-blog`, …). `og-default.jpg` is the site-wide fallback.
- Static pages set the card through `Layout`'s `image` prop; the mapping is in the docs. Pages with their own `ogImage` variable need both the absolute URL (JSON-LD) and the root-relative path (hero) updated.
- The generator needs `sharp` (declared in `devDependencies`) and the brand fonts installed locally (Space Grotesk Bold, IBM Plex Mono). It is an authoring tool, not part of the build; CI never runs it.
- Keep `public/assets/images/` limited to files that are actually referenced. Delete the `.jpg` and `-600.jpg` together when a post is removed.
